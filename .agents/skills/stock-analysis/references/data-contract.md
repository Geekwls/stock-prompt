# 数据契约与覆盖率规则

## 数据源优先级

```text
P0 用户提供且可核验的数据
P1 结构化行情接口或数据库
P2 交易所公告、定期报告、公司公告与公司 IR
P3 可追溯到原始出处的权威财经数据
P4 网络检索，用于发现线索和补充上下文
P5 模型推断，只能参与解释，不能生成事实或精确数值
```

网络搜索摘要不能直接作为 MA、ATR、RS、POC、换手率、赔率或财务比率的数值来源。引用新闻时记录事件发生日与报道日。

**MCP 优先路由**：宿主已挂载 `marketgraph-data` MCP 时，按下列路由优先取数，但公开网关输出按 P3 记录并保留 `source`、`data_status` 与时点；`data_status != ok` 的数据不得参与计算或输出方向结论。未挂载或调用失败时回退网络检索，并严格执行下述缺省审计。

- **个股行情与结构**：`get_stock_kline`（默认 750 日前复权日 K + MA20/50/120/250/500 均线矩阵 + 3年分位 + 周线共振 + 量比/120日量能分位）、`get_stock_quote` 与 `get_stock_timeline` 共同决定数据模式。120 根复权 K 线与双基准齐全时进入 `full`；20–119 根进入 `reduced`；次新、复牌或突发事件进入 `event`，不得因无法进入 full 而放弃全部分析。
- **L1 市场环境专用**：`get_index_kline`（宽基指数逐日涨跌幅，`count` 最大 130，覆盖 L4 的 120 日窗口）、`get_market_breadth`（红盘率与涨跌家数，最新交易日为精确口径，历史交易日为情绪池替代并以 `breadth_precision` 标注）、`get_market_sentiment`（两市成交额与涨停池）。三者均为 P3 结构化公开网关，优先于网页搜索，且不得以个股数据替代。
- **L2 板块证据**：`get_sector_fund_flow`（当日全行业资金流榜；`days=2-10` 回补 N 日主力净流入历史、累计净额与趋势定性）、`get_sector_kline`（板块指数日K序列、MA5/10/20/60 与 5/20/60 日区间涨幅，兼作 L4 的行业基准）；东财板块源不可用时按公共契约改用 `get_basket_index` 传入板块主要成分股构造等权代理序列（标注"代理序列"与覆盖度，仅作方向性 RS 对照）。
- **席位与公司质量**：`get_longhubang_detail`（龙虎榜席位穿透，含机构专用逐席位净额明细 `org_seat_net_details`）；`get_company_quality`（财务、商誉、解禁与排雷筛查）。
- **服务端预计算标签的边界**：`get_stock_kline` 返回的 `wyckoff_multi_timeframe`、`weekly_alignment`、`macro_wyckoff_phase` 等结构标签按 P3 线索记录，只能用于宏观定调与交叉核对；L5 的威科夫主假设、竞争假设及 `Confirmed/Probable` 分级必须由模型基于 OHLCV 独立完成，不得直接照抄服务端标签充当结构确认——服务端标签与模型独立结论冲突时，必须并列披露并解释分歧。
- 公司审计、监管与事件风险仍须交易所公告或定期报告核验。

## 数据新鲜度与证据编号

- 每条关键事实使用唯一编号 `F01`、`F02`……，至少记录事实、来源层级、来源名称/链接、数据或事件日期、获取日期和口径。
- 行情与技术指标原则上不超过 1 个交易日；盘中数据必须带具体时间。财务数据标注所属报告期，公告与催化剂同时记录公告日和事件发生日。
- 超过新鲜度窗口的证据可以保留作历史背景，但不得直接支持“当前”结论；来源日期或口径缺失时标记 `N/A`。
- 结论、主假设、竞争假设和风险判断均应回指至少一个 `Fxx`；纯模型推断不得伪装成事实证据。

## 数据模式与能力边界

分析前至少确认：

- 证券代码、交易所、证券简称和研判时点。
- 前复权日线 OHLCV 的实际根数与可用区间。
- 复权方式、停牌、除权除息、拆并股及上市未满周期情况。
- 同期宽基指数与所属行业指数行情。
- 当前价格是盘中快照还是收盘价，并带时间戳。

调用 `resolve_stock_data_mode` 后执行：

### `full`

条件：至少120根前复权日线、同期宽基和行业基准完整，且不属于需要独立定价的突发事件状态。

- 允许双基准 RS、长周期结构、位置、赔率和所选模型内部区间分。
- 评分只可与相同 `model_selected + formula_version` 比较。

### `reduced`

条件：至少20根前复权日线，但不足120根或基准不完整。

- 允许短窗口收益、成交量、可观察结构与条件情景。
- 禁止长期 RS、完整威科夫确认、综合分和跨模型排名。

### `event`

适用于次新、重组复牌、重大事件或不足20根有效日线。以事件可信度、流通盘、换手、竞价/分时和可交易性为核心。

- 有实时价格、换手和分时证据时，可以做条件化事件分析。
- 禁止强造长期 RS、完整威科夫阶段、长期过热阈值和综合分。
- 停牌时可以分析事件事实与风险，但不得输出盘中执行条件。

数据模式是输出能力约束，不得被总覆盖率、基本面完整度或模型主观判断覆盖：

1. 不得把 reduced/event 的短窗口观察包装成长期结论。
2. 不得用搜索摘要、未复权序列或不同截止日数据恢复缺失评分。
3. 禁止综合评分不等于禁止列示事实、风险和下一验证条件。
4. 模式变化必须写入 Artifact 与 Handoff，后续数据补齐时才能升级。

## 数据覆盖率权重

| 数据组 | 权重 | 有效条件 |
|---|---:|---|
| 复权行情与成交数据 | 25% | 时间戳、复权口径、有效OHLCV齐全 |
| 市场与行业基准 | 12% | 同期宽基和行业指数可比 |
| 板块归属与横截面 | 10% | 行业口径明确且排名样本一致 |
| 公告与催化 | 13% | 事件日期、原始来源和状态可核验 |
| 财务质量与估值 | 20% | 最新报告期、同比/环比口径明确 |
| 治理与重大风险 | 10% | 减持、解禁、质押、问询等已检查 |
| 目标位与流动性 | 10% | 结构位、成交约束和成本假设明确 |

覆盖率只按已验证数据计分。某数据组部分可用时，列出子项并按实际比例计算，不得凭印象给出整数。

报告必须附覆盖率审计表，逐组列出计划权重、已验证子项、取得权重、缺失项和对应证据编号。`Data Coverage` 必须由表中取得权重求和得到，不得写“约75%”等无法复算的估计值。

`Scored Weight` 与 `Data Coverage` 是两个不同指标：前者表示实际进入所选模型评分的模块权重，后者表示已验证数据占计划数据的比例。`reduced/event` 模式即使部分模块可用，也禁止输出综合分。

`source_count` 统计唯一、可打开的原始文档或URL数量，不统计证据行数，也不得把同一来源的多个指标重复计数。

## 覆盖率与输出限制

- `>=85%`：full 模式可输出模型内评分区间；是否高置信仍取决于证据一致性。
- `70%–84%`：full 模式可评分，但证据置信度最高为“中”。
- `50%–69%`：完整列示八层，仅输出条件判断，不给综合分或风险暴露等级。
- `<50%`：输出数据审计、已知事实和待补清单，三轴结论均为“暂不评级/数据不足”。

数据不足与逻辑证伪必须严格区分。
