# 数据契约与覆盖率规则

## 数据源优先级

```text
P0 用户提供且可核验的数据
P1 结构化行情接口或数据库
P2 交易所公告、定期报告、公司公告与公司 IR
P3 可追溯到原始出处的权威财经数据
P4 网络检索，用于发现线索和补充上下文
P5 模型推断，只能参与解释，不能生成事实或精确数值
```

网络搜索摘要不能直接作为 MA、ATR、RS、POC、换手率、赔率或财务比率的数值来源。引用新闻时记录事件发生日与报道日。

**MCP 优先路由**：宿主已挂载 `marketgraph-data` MCP 时，可优先调用 `get_stock_kline`、`get_stock_quote`、`get_stock_timeline`、`get_company_quality` 与 `get_longhubang_detail`，但公开网关输出按 P3 记录并保留 `source`、`data_status` 与时点。仅 `get_stock_kline` 返回 `adjustment: qfq`、`data_status: ok` 且至少 120 根 K 线时，可通过行情结构门槛；公司审计、监管与事件风险仍须交易所公告或定期报告核验。未挂载或调用失败时回退网络检索，并严格执行下述缺省审计。

## 数据新鲜度与证据编号

- 每条关键事实使用唯一编号 `F01`、`F02`……，至少记录事实、来源层级、来源名称/链接、数据或事件日期、获取日期和口径。
- 行情与技术指标原则上不超过 1 个交易日；盘中数据必须带具体时间。财务数据标注所属报告期，公告与催化剂同时记录公告日和事件发生日。
- 超过新鲜度窗口的证据可以保留作历史背景，但不得直接支持“当前”结论；来源日期或口径缺失时标记 `N/A`。
- 结论、主假设、竞争假设和风险判断均应回指至少一个 `Fxx`；纯模型推断不得伪装成事实证据。

## 行情硬门槛

计算技术指标前至少确认：

- 证券代码、交易所、证券简称和研判时点。
- 至少120个交易日的前复权日线 OHLCV；不足时明确可用区间。
- 复权方式、停牌、除权除息、拆并股及上市未满周期情况。
- 同期宽基指数与所属行业指数行情。
- 当前价格是盘中快照还是收盘价，并带时间戳。

行情硬门槛是输出限制，不得被总覆盖率、基本面数据完整度或模型主观判断覆盖。缺少上述任一核心条件时必须同时执行：

1. L4–L7 统一记为 `N/A`；相关现象只能放入“定性观察”，不得参与评分。
2. 结构与位置判为“暂不评级”，证据置信度判为“数据不足”。
3. 不输出综合评分区间、精确 RS、威科夫 `Probable/Confirmed`、动态过热阈值或风险收益比。
4. 不得一边声明行情数据不足，一边继续用零散交易日、52周高低点或搜索摘要恢复技术评分。

只有完整通过行情硬门槛后，L4–L7 才允许参与综合评分。

## 数据覆盖率权重

| 数据组 | 权重 | 有效条件 |
|---|---:|---|
| 复权行情与成交数据 | 25% | 时间戳、复权口径、有效OHLCV齐全 |
| 市场与行业基准 | 12% | 同期宽基和行业指数可比 |
| 板块归属与横截面 | 10% | 行业口径明确且排名样本一致 |
| 公告与催化 | 13% | 事件日期、原始来源和状态可核验 |
| 财务质量与估值 | 20% | 最新报告期、同比/环比口径明确 |
| 治理与重大风险 | 10% | 减持、解禁、质押、问询等已检查 |
| 目标位与流动性 | 10% | 结构位、成交约束和成本假设明确 |

覆盖率只按已验证数据计分。某数据组部分可用时，列出子项并按实际比例计算，不得凭印象给出整数。

报告必须附覆盖率审计表，逐组列出计划权重、已验证子项、取得权重、缺失项和对应证据编号。`Data Coverage` 必须由表中取得权重求和得到，不得写“约75%”等无法复算的估计值。

`Scored Weight` 与 `Data Coverage` 是两个不同指标：前者表示实际进入综合评分的层级原始权重，后者表示已验证数据占计划数据的比例。行情硬门槛失败时，即使其他层级可评分，也禁止输出综合评分。

`source_count` 统计唯一、可打开的原始文档或URL数量，不统计证据行数，也不得把同一来源的多个指标重复计数。

## 覆盖率与输出限制

- `>=85%`：可输出完整评分区间；是否高置信仍取决于证据一致性。
- `70%–84%`：可评分，但证据置信度最高为“中”。
- `50%–69%`：完整列示八层，仅输出条件判断，不给综合分或风险暴露等级。
- `<50%`：输出数据审计、已知事实和待补清单，三轴结论均为“暂不评级/数据不足”。

数据不足与逻辑证伪必须严格区分。
