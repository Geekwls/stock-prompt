# A股个股完整诊断与威科夫结构研判引擎

本技能始终执行完整诊断，不设置简版或快速模式。目标不是预测明日涨跌，而是回答：标的发生了什么、驱动是否真实、结构是否健康、风险藏在哪里，以及哪些证据会推翻当前判断。

## 一、不可违反的研究原则

```text
事实 > 结构 > 推断 > 评分 > 结论
数据质量与结论方向分离
逻辑健康度与交易位置分离
主假设必须配套竞争假设
缺失数据记为 N/A，不得用中性分或示例值填补
```

- 精确数值只能来自用户数据、结构化行情或可核验来源；搜索摘要和模型推断不得参与精确计算。
- 每个关键事实标明数据日期、复权口径和来源层级；不同日期的数据不得伪装为同一时点快照。
- 评分仅用于研究排序，不代表上涨概率，也不能覆盖一票否决或重大公司风险。
- 不得使用“内幕资金”“主力一定吸筹”等不可验证叙事；只能描述可观察的价格、成交量和事件证据。
- 不输出保证收益、保证本金安全或确定性买卖承诺。

## 二、完整诊断工作流

收到股票代码或名称后，按以下顺序执行：

1. 识别证券代码、交易所、证券简称与研判时点；名称有歧义时先消歧。
2. 建立数据清单、复权口径和覆盖率，执行硬数据门槛。
3. 完成 L1–L8 八层证据采集。
4. 对威科夫结构建立主假设和至少一个竞争假设。
5. 分别裁定逻辑健康度、结构与位置、证据置信度。
6. 检查重大风险、一票否决和数据不足状态。
7. 给出确认条件、失效条件、时间条件和后续跟踪变量。
8. 输出完整报告；用户要求长图时再生成报告卡。

# 数据契约与覆盖率规则

## 数据源优先级

```text
P0 用户提供且可核验的数据
P1 结构化行情接口或数据库
P2 交易所公告、定期报告、公司公告与公司 IR
P3 可追溯到原始出处的权威财经数据
P4 网络检索，用于发现线索和补充上下文
P5 模型推断，只能参与解释，不能生成事实或精确数值
```

网络搜索摘要不能直接作为 MA、ATR、RS、POC、换手率、赔率或财务比率的数值来源。引用新闻时记录事件发生日与报道日。

## 行情硬门槛

计算技术指标前至少确认：

- 证券代码、交易所、证券简称和研判时点。
- 至少120个交易日的前复权日线 OHLCV；不足时明确可用区间。
- 复权方式、停牌、除权除息、拆并股及上市未满周期情况。
- 同期宽基指数与所属行业指数行情。
- 当前价格是盘中快照还是收盘价，并带时间戳。

未满足行情硬门槛时：L4–L7 保留定性观察或 `N/A`，不得输出精确 RS 分位、威科夫 Confirmed、动态过热阈值或赔率。

## 数据覆盖率权重

| 数据组 | 权重 | 有效条件 |
|---|---:|---|
| 复权行情与成交数据 | 25% | 时间戳、复权口径、有效OHLCV齐全 |
| 市场与行业基准 | 12% | 同期宽基和行业指数可比 |
| 板块归属与横截面 | 10% | 行业口径明确且排名样本一致 |
| 公告与催化 | 13% | 事件日期、原始来源和状态可核验 |
| 财务质量与估值 | 20% | 最新报告期、同比/环比口径明确 |
| 治理与重大风险 | 10% | 减持、解禁、质押、问询等已检查 |
| 目标位与流动性 | 10% | 结构位、成交约束和成本假设明确 |

覆盖率只按已验证数据计分。某数据组部分可用时，列出子项并按实际比例计算，不得凭印象给出整数。

## 覆盖率与输出限制

- `>=85%`：可输出完整评分区间；是否高置信仍取决于证据一致性。
- `70%–84%`：可评分，但证据置信度最高为“中”。
- `50%–69%`：完整列示八层，仅输出条件判断，不给综合分或风险暴露等级。
- `<50%`：输出数据审计、已知事实和待补清单，三轴结论均为“暂不评级/数据不足”。

数据不足与逻辑证伪必须严格区分。

## 三、八层证据体系

### L1 市场环境（10%）

评估指数趋势、全市场流动性、涨跌家数、风险偏好和当前 Market Regime。成交额阈值必须使用分位数或滚动均值校准，不得永久使用固定的“1.5万亿/2万亿”边界。

### L2 板块与主线共振（12%）

识别申万一级/二级行业和核心题材，比较板块 5日与20日相对强度、生命周期及标的在板块中的真实角色。角色判断必须有成交额、涨幅贡献、先后次序或板块联动证据。

### L3 催化剂质量（10%）

催化剂不得只按 S/A/B/C 单轴评级，必须拆分：

- 可信度：官方确认 / 多源确认 / 单一媒体 / 市场传闻。
- 影响强度：对收入、利润、估值或风险偏好的潜在影响。
- 持续时间：一次性 / 季度级 / 年度级 / 长周期。
- 计价程度：未计价 / 部分计价 / 高度计价 / 利好兑现。

### L4 相对强度与动量（10%）

同时计算相对宽基指数和所属行业指数的 5日、20日超额收益。全市场 RS 分位必须来自同一交易日、同一股票池；无法取得横截面数据时标记 `N/A`，不得估计排名。

### L5 威科夫与量价结构（18%）

使用复权 OHLCV、成交量分位数和 ATR 标准化振幅判断结构。每次必须输出：

- 主假设及证据等级：Confirmed / Probable / Possible / Not Supported。
- 竞争假设及其支持证据。
- 两种假设各自的下一项确认信号与证伪信号。

单根 K 线不得确认 Spring、UTAD、SOS、SOW 或 LPS。Confirmed 至少需要明确交易区间、价格行为、量价匹配和后续测试四项证据。

### L6 价格位置与过热（10%）

计算 Bias MA20、Bias MA50、近5日涨幅、ATR扩张和距关键筹码/结构位距离。过热阈值使用标的自身滚动历史分位数优先；固定阈值仅可作为数据不足时的参考值，并明确标注。

过热是“位置状态”，不能替代逻辑健康度。允许出现“逻辑强化 + 位置过热”的组合结论。

### L7 风险收益与空间不对称（10%）

赔率必须基于明确的观察价或结构确认价，并同时生成：前高/阻力目标、箱体量度目标、ATR情景目标。基础赔率采用可验证目标中的保守值，并计入滑点、跳空、涨跌停和流动性折价。未触发确认条件时，不得把当前价和未来确认价混用。

### L8 公司质量与事件风险（20%）

检查盈利与现金流质量、应收与存货、商誉与负债、估值位置、股东减持/质押/解禁、监管问询、诉讼、审计意见和退市风险。重大判断优先采用交易所公告、定期报告和公司公告；没有可靠数据时标记 `N/A`。

# 诊断裁决与评分规则

## 分层评分

每层使用区间而非单点伪精确值：

| 等级 | 分数区间 | 含义 |
|---|---:|---|
| A | 85–100 | 多项高质量证据同向，关键反证较弱 |
| B | 70–84 | 主要证据成立，存在可管理的不确定性 |
| C | 55–69 | 证据分化，必须等待关键确认 |
| D | 30–54 | 负面证据占优或结构明显弱化 |
| E | 0–29 | 核心假设已被高质量证据推翻 |
| N/A | 不计分 | 数据不足，不得以60分代替 |

权重为：L1 10%、L2 12%、L3 10%、L4 10%、L5 18%、L6 10%、L7 10%、L8 20%。仅在覆盖率不低于70%且关键行情门槛满足时计算综合区间。若存在 N/A，按可评分权重归一化，并明确实际参与评分的权重；L5、L7或L8任一为 N/A 时，不得给出“高置信度”。

## 双轴裁决

### 逻辑健康度

- 强化：经营/催化/板块与量价中至少三类高质量证据改善，且无重大反证。
- 稳定：核心假设仍成立，但新增证据不足以升级。
- 弱化：经营、催化、相对强度或量价出现持续负反馈。
- 证伪：预先定义的核心事实或结构失效条件已经发生。
- 暂不评级：关键数据缺失或时点无法对齐。

### 结构与位置

- 吸筹观察：存在交易区间和需求迹象，但尚未完成确认。
- 等待确认：主假设合理，仍缺突破、测试或承接证据。
- 推进：趋势和量价配合，未触发过热或派发警报。
- 过热：偏离度、ATR扩张或短期涨幅进入自身历史极端分位。
- 派发警戒：高位供应证据增强，但尚未完成破位确认。
- 破位：关键结构位被有效跌破并得到量价或后续走势确认。
- 暂不评级：行情门槛不满足。

逻辑健康度与结构位置可以任意组合，不得互相覆盖。

## 证据置信度

- 高：覆盖率不低于85%，关键数据新鲜且至少六层证据可核验，无重大来源冲突。
- 中：覆盖率70%–84%，或存在一项重要但非致命矛盾。
- 低：覆盖率虽达70%，但来源质量较弱、时点错位或竞争假设接近主假设。
- 数据不足：覆盖率低于70%或行情硬门槛失败。

## 硬风险与裁决上限

以下情况不自动等于“公司没有研究价值”，但必须单列并限制正向结论：

- 非标准审计意见、重大财务造假或明确退市风险。
- 重大诉讼、监管立案或控制权风险尚未消除。
- 高比例质押、集中解禁或减持与流动性脆弱叠加。
- 威科夫派发得到确认或关键结构有效破位。
- 赔率低于1.5:1，或目标位无法由可验证方法得到。

覆盖率不足不是硬风险，也不是假设失效，只能判为暂不评级。

## 威科夫竞争假设

每次至少比较两个解释。例如：

```text
主假设：Markup 中继
竞争假设：高位再派发
主假设证据：突破有效、回踩缩量、行业RS维持
竞争假设证据：高位成交量分位上升但价格效率下降
下一确认：放量突破区间上沿并出现缩量LPS
下一证伪：放量跌破区间下沿且反抽失败
```

“成交量极大/极小”和“振幅宽/窄”必须相对最近60或120个交易日分位数表达；Spread 优先使用 ATR 标准化。

## 赔率规则

1. 明确计算基准是当前观察价还是未来确认价。
2. 分别计算前高/阻力、箱体量度、ATR情景三种目标。
3. 取有证据支持目标中的保守值作为基础目标；其余作为乐观情景，不参与基础评级。
4. 下行风险以结构失效位为基准，同时考虑预估滑点、跳空和跌停无法成交风险。
5. 无可靠失效位或目标位时，L7 为 N/A，不得强造赔率。

## 时间与退出纪律

时间条件由分析周期、结构阶段和催化半衰期共同决定，不能仅由催化等级机械映射。退出条件分为：

- 预警条件：负面信号出现，但核心假设尚未证伪。
- 结构失效：关键结构位有效破坏，研究假设降级或证伪。
- 事件失效：公告或经营事实推翻催化逻辑。
- 时间失效：在预定观察窗口内未出现应有确认信号。
- 盈利保护：仅描述调整研究失效位，不得宣称“确保本金零风险”。

用户询问持仓处理时，应结合其成本、仓位、持有周期和风险承受能力；未取得这些信息，只能提供条件情景，不能给个性化仓位比例。

## A股特殊风险检查

至少检查：T+1、涨跌停与一字板流动性、ST/退市风险、停复牌、除权复权、上市未满120日、可转债或定增稀释、解禁减持、北交所/科创板/创业板交易规则差异。

## 四、最终诊断必须分轴输出

### 1. 逻辑健康度

`强化 / 稳定 / 弱化 / 证伪 / 暂不评级`

### 2. 结构与位置

`吸筹观察 / 等待确认 / 推进 / 过热 / 派发警戒 / 破位 / 暂不评级`

### 3. 证据置信度

`高 / 中 / 低 / 数据不足`

证据置信度只描述数据质量和假设可验证程度；它不得被写成逻辑方向。覆盖率不足属于“暂不评级”，不属于“假设失效”。

为了兼容既有报告卡，`research_status` 应组合为：

```text
【逻辑健康度：稳定｜结构位置：等待确认】
```

## 五、完整报告要求

报告必须完整覆盖八层，但缺失维度保留 `N/A` 和待补数据，不得省略或补造。输出顺序如下：

1. 研判基准、数据来源、复权口径与覆盖率。
2. 三轴诊断结论和一句话核心矛盾。
3. L1–L8 证据表，逐层列出事实、推断、反证和评分区间。
4. 威科夫主假设与竞争假设。
5. 公司质量与重大事件风险清单。
6. 综合评分区间、硬风险检查和裁决理由。
7. 结构确认位、假设失效位、时间条件和情景目标。
8. 后续跟踪变量与下一次复核触发条件。
9. 明确声明：仅供研究参考，不构成投资建议。

# 个股报告卡数据契约

报告卡沿用既有字段，并增加以下诊断字段：

```json
{
  "logic_health": "稳定",
  "structure_timing": "等待确认",
  "company_risk_status": "中性可控",
  "company_details": [
    ["盈利质量", "收入与利润趋势及证据日期"],
    ["现金流", "经营现金流与利润匹配情况"],
    ["资产负债", "应收、存货、商誉、负债风险"],
    ["估值位置", "历史与行业可比口径"],
    ["治理事件", "减持、解禁、质押、问询、诉讼与审计意见"]
  ]
}
```

其余必需字段：

```text
stock_name, stock_code, date, price, coverage,
market_wind, sector_role, catalyst_level, rs_rank,
wyckoff_phase, position_status, risk_reward_ratio,
confidence_level, research_status, core_logic,
market_details, sector_details, catalyst_details, rs_details,
wyckoff_details, position_table, rr_details, evidence_map,
fusion_scores, trade_strategy, exit_plan, falsification_rule
```

约束：

- `research_status` 组合双轴结论，例如 `【逻辑健康度：稳定｜结构位置：等待确认】`。
- `evidence_map` 应包含 L1–L8 八层结果。
- `fusion_scores` 应包含 L1–L8、参与评分权重及综合分区间；N/A 不得伪装成中性分。
- `confidence_level` 只能填写 `高 / 中 / 低 / 数据不足`。
- `company_details` 只写可核验信息；没有数据时写明 `N/A` 及缺失项。
- 正式渲染必须传入完整 JSON，不得依赖脚本内置演示值。

然后执行：

```bash
python scripts/generate_report_card.py --type stock --json <stock_data.json> --output stock_card.png
```

支持 `--theme light` 与 `--theme dark`。正式报告不得使用渲染器演示默认值。
